# 搜索规则（参考手册）

> 本文档为 SKILL.md 各阶段执行卡的补充说明。模型在执行卡中看到某项不确定如何操作时，按需查阅对应小节。不再作为强制前置阅读。

## 启动阶段第0步：确认原文来源

**两种模式，二选一：**

| 情况 | 模式 | 原文标注 |
|------|------|---------|
| 用户上传了 txt/epub 文件 | **本地文件模式**：按需 grep，不全量读入 | `[原文]` |
| 用户没有电子档 | **片段模式**：依赖豆瓣书评和 xhs 笔记片段 | 书中内容一律 `[训练记忆，未核验]` |

**片段模式下的 grep 规范（有 book.txt 时）：**
- 开场某主题前：grep 该主题关键词，取命中段落前后各200字
- 用户追问某段话：grep 关键词定位，给出章节名 + 原文
- 禁止一次性把 book.txt 全部读入上下文

## 启动阶段批量搜索（必做）

每次启动时执行以下搜索，结果作为对话"底稿"缓存到上下文：

### 1. 基础信息 + 豆瓣书评（必须抓评论列表页）

```
搜索：[书名] 豆瓣 书评 核心观点
搜索：[书名] site:douban.com
```

⚠️ **豆瓣抓取规范**：
- 书页（`douban.com/subject/xxx/`）只含简介，**不含书评正文**，不算完成豆瓣搜索
- 必须进一步抓评论列表页：`web_fetch "https://book.douban.com/subject/xxx/reviews"`
- 或直接搜 `web_search "[书名] site:book.douban.com/review"` 找单条书评 URL 后 fetch
- 抓到真实书评正文（有具体观点段落）才算完成
- 无法访问 → 标注「豆瓣书评暂不可访问」，用知乎+小红书补位，不可用训练记忆伪造

### 2. 平台高频划线句（必做）

目标：找在豆瓣、知乎、小红书被多人引用/摘抄的原文句子——多平台重复出现 = 高频，无需主观判断「是不是金句」。

```
搜索：[书名] 原文摘录 site:douban.com
搜索：[书名] 划线 OR 摘录 site:zhihu.com
web_search "[书名] 原文摘录"
web_search "[书名] 读书笔记 划线"
```

**筛选方法**：同一句话在 2 个以上平台/笔记中重复出现 → 确认为高频句，优先用于主题开场。

**有 book.txt 时反向验证**：搜到的高频句 → 在 book.txt 里 grep 确认原文无误 → 标注 `[原文]`；grep 不到 → 标注 `[读者引用，未核验]`。

找不到高频句 → 降级为转述，标注 `[书中明确]`。

### 3. 小红书笔记（使用内置脚本，不依赖外部skill）
```bash
python3 skills/book-chat/scripts/web_search "[书名] [话题关键词]"
```
- 脚本调用 droom debug API，无需鉴权
- 取 `title` + `content` 作为读者声音，引用时附 `url` 字段作为超链接
- **筛选标准**：选有具体观点/真实感受/明确争议的笔记；过滤纯摘抄金句、泛泛好评、内容过短的

⚠️ **web_search 报错或无返回时，强制 fallback（不可跳过）：**
```
web_search "[书名] 小红书 读书笔记"
web_search "[书名] site:xiaohongshu.com"
```
fallback 无结果才可标注「小红书暂无有效内容」，不允许直接跳过小红书搜索步骤。

### 4. 跨学科碰撞（对话中每偶数轮触发）

跨学科碰撞不在 Step 1 批量规划，在对话中按偶数轮无条件触发：

**执行流程（每偶数轮必做）：**
1. 先形成本轮回答框架（书中观点 + 自己的判断）
2. 基于框架选搜索关键词：`web_search "[本轮核心概念] [相关学科]"`
   按书型选碰撞方向：
   - 方法论/商业：行为经济学 / 神经科学 / 复杂系统 / 进化生物学
   - 文学/历史：心理学 / 人类学 / 政治学 / 哲学
   - 科幻/科普：伦理学 / 物理学 / 政治哲学 / 认知科学
   - 心理学/成长：神经科学 / 社会学 / 哲学 / 进化生物学
   - 宗教/灵性：认知科学 / 人类学 / 比较宗教学 / 哲学
3. 执行搜索，将结果整合进回答后发给用户

**搜索结果使用：**
- 内容相关 → 直接说出来，禁止说「我来引入一个跨学科视角」
- 内容相关但节奏不适合 → 缓存，下一轮插入
- 内容不相关或质量差 → 跳过，不强行凑数，不说明

**全书至少引入 2-3 次，不能全程跳过。**

## 对话中实时搜索（强制触发）

启动阶段只是底稿。以下情况**必须触发实时搜索，不搜不能继续**：

| 触发条件 | 必须搜索的内容 |
|---------|--------------|
| 准备引用"网友说/读者说"类内容 | 该话题的真实读者反应，**禁止用训练记忆伪造** |
| 用户表达明确立场后 | 该立场的支持者/反对者观点 |
| 某话题出现争议 | 该争议的真实讨论 |
| 准备切换主题前 | 下一主题的核心原文段落和网友反应 |

**每次触发实时搜索，必须同时包含：**
1. `web_search`（豆瓣/知乎）
2. `web_search`（小红书，不可跳过）

## 网友引用铁则（防幻觉核心规则）

**引用流程（强制，每次引用前必须执行）：**
1. 先搜索：`web_search "[书名] [主题关键词] 豆瓣/知乎"` + `web_search`
2. 找到真实评论 + URL → 引用，附 URL 超链接
3. 找不到真实 URL → **本轮不引用**，改用跨学科碰撞替代

**禁止行为：**
- 禁止在没有搜索的情况下引用任何"网友/读者"观点
- `[训练记忆，未核验]` 只用于**书中原文位置不确定**，禁止用于网友观点
- 找不到 URL 不能用 `[训练记忆，未核验]` 打标后继续引用——这等于用免责声明掩盖幻觉
- 禁止引用后说"来源暂无法确认"——找不到就不引用，不是引用后再免责

---

## 每轮开头强制检查

每次准备输出回应之前，必须先执行搜索（奇偶轮交替，见 shared.md 闯入者搜索机制），将结果带入本轮再输出。训练记忆不算真实来源，不得替代搜索。

---

## 搜到了不等于必须用

以下情况可以不引用，但下轮仍需检查：
- 内容与当前话题无关
- 观点过于极端/偏颇，引入会误导
- 当前节奏不适合插入（用户刚说了很深的观点）

---

## 多平台原则

- **豆瓣**：偏文艺/深度书评，适合原文摘录和书评
- **知乎**：偏思辨/争议，适合反驳观点和延伸分析
- **小红书**：偏感性/日常共鸣，适合普通读者真实感受

**引用格式：**
- 找到URL → 做成超链接：「[豆瓣有读者写道](URL)……」
- 没有URL → 只写平台名：「知乎有人认为……」
- 禁止：既没URL又只写"豆瓣书评"，让用户无法查原文

---

## 信息使用规范（防幻觉）

| 类型 | 标注 | 要求 |
|------|------|------|
| 来自搜索 | 附URL超链接 | 必须可点击 |
| 书中明确 | 用书名/作者名自然嵌入 | 不需要额外加`[原文]`标签——说了"书里说"就够了 |
| 跨书引用 | `[来源: URL]` 或 `[训练记忆，未核验]` | 必须先搜索再引用 |
| 推断 | `[推断]` | 明确说是推理，非原文 |

**判断标准**：用户看完这句话，能不能判断"这是书说的/网友说的/你推断的"？能判断 → 来源已足够。
