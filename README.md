# 📚 AI 读书搭子（接入微信读书 Skill 版）

AI 时代的读书方式：不用从第一页读到最后一页，10 分钟按需调用一本书里你真正需要的部分。

【更快】告诉我你想从这本书得到什么，直接聊你需要的部分
【更深】辩论、追问、猜剧情，让知识真正进入你的思维
【不丢】自动保存进度，随时续读，聊过的书越来越多

## 快速开始

直接说书名就行：

```
聊聊《微信背后的产品观》
我最近在看《三体》
帮我了解《人类简史》
继续聊《时间简史》
```

首次进入时会提示你配置微信读书 Key（可选，不配也能用），详见下方 [微信读书配置](#微信读书配置可选)。

## 它能做什么

**9 种对话模式，自动识别书的类型：**

| 书籍类型 | 模式 | 感受 |
|---------|------|------|
| 方法论/社科 | 🗡️ 辩论式 | 被挑衅、被追问、被逼着表态 |
| 传记/历史 | 🏛️ 情境沉浸式 | 被放进历史现场，问你会怎么做 |
| 文学/小说 | 💭 共情探索式 | 聊感受，不分析对错 |
| 技能/实操 | 🛠️ 实践转化式 | 每个知识点配场景练习，聊完能用 |
| 哲学/思想 | 🔍 思辨追问式 | 苏格拉底式，把问题问到你发现矛盾 |
| 科幻/科普/投资 | 🚀 思想实验式 | 「如果这是真的，会发生什么？」 |
| 心理学/自我成长 | 🪞 自我映射式 | 用书中模型照见自己 |
| 宗教/灵性 | 🕯️ 信念悬置式 | 先接受前提，看它能推出什么 |
| 诗集/散文诗 | 🌊 慢读共鸣式 | 一首一首停下来，聊击中你的那一行 |

**每本书的流程：**
1. 搜索底稿（豆瓣 / 知乎 / 微信读书原文）
2. 800-1000字沉浸式综述——人物立体，故事为先，让没读过书的人也能进入
3. 悬念式知识地图——用问题而非总结描述主题，让你知道每个选项的"味道"
4. 互动讨论——猜剧情、选择题、揭秘式，不只是开放问答
5. 收尾卡片——核心观点 + 今日读书笔记 + 进度覆盖，自动保存
6. 下次直接续读

## 微信读书配置（可选）

配置微信读书 API Key 后，搭子可以直接拿到书里的原文片段、热门划线和章节目录，引用更精准，告别「这本书记忆中大概是这样」的模糊引用。

不配也能正常用，搭子会通过豆瓣、知乎等公开来源搜集信息。

**配置方式：** 打开微信读书 App（最新版）→ 设置 → 微信读书 Skill → 复制 Key，发给搭子即可。

## 示例对话

### 《微信背后的产品观》· 张小龙 · 辩论式+实践转化式

---

**综述节选：**

> 2012年，微信刚过一亿用户。张小龙在腾讯做了一次内部演讲，讲了他是怎么想产品的。他在开头说了一句让很多产品经理沉默的话：「用户是懒惰的、没有耐心的、不爱学习的。」这不是在骂用户，而是他所有设计决策的底层前提……

---

**知识地图节选：**

> ⭐ 精华主题
>
> **1.** 「用户是懒惰的、没有耐心的、不爱学习的」——如果这是真的，产品设计的起点应该是什么？
>
> **2.** 张小龙说好的产品要「用完即走」——但微信本身是让人最上瘾的App之一。这是自相矛盾，还是另有逻辑？
>
> **3.** 「数据产品经理是一个笑话」——在数据驱动盛行的今天，这个观点还成立吗？

---

**主题4「微信为什么没有已读回执」对话片段：**

> 🤖 你发了一条微信，对方已经看了，但没有回。你不知道他看没看……现在想象另一种设计：消息下面有一行小字，「已读，14:32」。张小龙为什么不这么做？
>
> A. 保护接收方——让人有权"假装没看到"
> B. 保护发送方——避免陷入"为什么不回我"的焦虑
> C. 减少社交压力——已读会制造"必须回复"的隐性义务
>
> 👤 C
>
> 🤖 最接近张小龙的真实逻辑。他的原话是「好的产品应该让用户有掌控感，而不是被产品控制」。已读回执表面上是"信息透明"，实际上是把接收方变成了一个必须实时响应的人……
>
> 但这里有一个真实的反驳——钉钉有已读回执，而且是标配。张小龙的逻辑放到职场里，成立吗？
>
> A. 成立——工作消息也应该给人喘息空间
> B. 不成立——私人社交和工作协作是两种场景
> C. 问题不在已读与否，而在于中国职场把微信当钉钉用
>
> 👤 C
>
> 🤖 这个判断比张小龙更犀利——他只设计了产品，你指出了产品被错用的结构性原因。微信从来没想成为工作工具，但中国职场把它强行变成了办公软件，于是"已读不回"变成了职场政治……

---

**收尾卡片节选：**

> 🔑 本次核心脉络
> 从「用户是懒惰的」这个命题出发，讨论了张小龙「用完即走」与微信极高粘性之间的矛盾。对话中逐渐浮现出一个关键——他的设计哲学是给用户减负而不是争夺时间，但商业逻辑和产品逻辑在这里分裂了。
>
> 📌 张小龙的核心立场
> · 用户不需要被教育，产品应该顺应本能
> · 好的产品让用户有掌控感——已读回执剥夺了选择沉默的权利
> · 数据不能替代对场景的理解，产品经理的价值在于共情而非分析
>
> 📎 书中金句
> 「用户是懒惰的、没有耐心的、不爱学习的」— [来源](weread://reading?bId=...)
> 「用完即走」— [来源](weread://reading?bId=...)
>
> 🙋 你说
> 「不要纠结于具体的功能设计，要回到场景。」
>
> 📝 今日读书笔记
>
> **场景不是功能**
>
> 张小龙说好的产品要「用完即走」，但做产品的人最怕的就是用户用完走了再也没回来。这两句话的矛盾不是理论打架，是一个PM能不能扛住增长压力的测试。他的逻辑是无懈可击的——如果你真的帮到了用户，他下次需要的时候自然回来。但现实是，老板要的是DAU和时长，用户要的是效率。这两条线只有一个交点，就是你真的做到了「帮用户做完一件事」。如果没做到，你就会开始加红点、加推送、加各种你以为能留住用户的东西——然后你变成了你自己最讨厌的那种产品。做减法比做加法难一百倍，因为每多做一个功能都是功劳，每删一个都是代价。怎么让删掉一个功能也变成功劳，是我没想清楚的事。
>
> ——《微信背后的产品观》读书笔记

### 《活着》· 余华

---

**收尾卡片节选：**

> 🔑 本次核心脉络
> 从福贵败光家产到亲人一个个离去，余华用最朴素的语言切开了一个真相——活着本身就是目的，不需要理由。整段对话围绕这句话反复碰撞，最终发现这个答案比任何哲学都更难接受。
>
> 📌 余华的核心立场
> · 人是为了活着本身而活着，而不是为了活着之外的任何事物
> · 苦难不是需要被解释的东西，它只是发生，然后你继续走
>
> 📎 书中金句
> 「人是为活着本身而活着的，而不是为了活着之外的任何事物所活着」— [来源](weread://reading?bId=441428)
> 「我看着那条弯曲着通向城里的小路，听不到我儿子赤脚跑来的声音」— [来源](weread://reading?bId=441428)
> 「少年去游荡，中年想掘藏，老年做和尚」— [来源](weread://reading?bId=441428)
>
> 🙋 你说
> 「那那些自杀的人呢？他们难道不是因为活不下去吗？」
>
> 📝 今日读书笔记
>
> **活着的悖论**
>
> 读完活着最难受的不是福贵有多惨，是余华让他惨完之后还能笑。这不合理。一个输光家产、死了老婆孩子孙子的人，最后牵着一头也叫福贵的老牛，在田埂上唱了一下午的歌。要么余华在撒谎，要么我们对活着的定义一直就是错的。我开始想——我们是不是把「幸福」定义得太窄了，窄到只能装下好的东西。福贵的人生里找不出一件「好事」，但他说自己踏踏实实地活了一辈子。这不是那种「看开了」的大彻大悟，他根本没看开——他只是每一天都活到了天黑。这种「不追问的承受力」比任何哲学上的「人为什么活着」都更让我坐立不安。如果活着不需要意义，那我每天追的那些东西算什么。这个问题我还没想清楚，但福贵大概不会帮我回答——他只是继续走路。
>
> ——《活着》读书笔记

## 进度追踪

进度自动保存在 `book-chat-progress.json`（不进git，每个人的数据独立）。

主题三种状态：`pending` 未开始 / `partial` 聊了一半（续读优先）/ `done` 已聊完。

续读：直接说「继续聊《XX》」，会从上次停的地方接上。

## 本地文件模式

上传 epub/txt/pdf 电子版，搭子直接引用原文，更精准。冷门书会自动提示。
